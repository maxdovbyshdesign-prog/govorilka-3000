# Говорилка 3000

Простой русский AAC-коммуникатор: алфавитная клавиатура из 33 букв, озвучивание названий букв и целого текста. Vite + Vanilla TypeScript + CSS. Без аккаунтов, бэкенда, аналитики, внешних шрифтов и API-ключей.

Приложение: **https://maxdovbyshdesign-prog.github.io/govorilka-3000/**

Репозиторий: https://github.com/maxdovbyshdesign-prog/govorilka-3000

## Запуск на Windows

Нужен Node.js 24 LTS. Дважды нажмите **Start.cmd**: он соберёт приложение и откроет браузер. Не закрывайте окно запуска, пока пользуетесь локальной версией. На первом запуске при отсутствии `node_modules` устанавливаются зависимости.

Либо из PowerShell в папке проекта:

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd run preview -- --port 4173
```

Откройте http://127.0.0.1:4173/. Для разработки: `npm.cmd run dev` (обычно порт 5173). В режиме разработки Service Worker не регистрируется; офлайн-режим проверяйте на production-сборке через preview или HTTPS-хостинг. `dist/index.html` нельзя запускать через `file://`.

## Как пользоваться

1. Нажимайте буквы — они появляются сверху. Последняя нажатая буква выделяется рамкой. Нажатие на текст не вызывает экранную клавиатуру.
2. Используйте «Пробел» и «Удалить». Каждое нажатие удаления убирает один последний символ.
3. Нажмите «Сказать», чтобы произнести всю фразу. Повторное нажатие запускает её заново. Пустая фраза не озвучивается.
4. «Очистить» открывает подтверждение. По умолчанию выбран безопасный вариант «Оставить текст»; Escape тоже отменяет очистку.
5. В «Настройках» можно выбрать русский голос, скорость (0.7 / 0.85), озвучивание букв и размер кнопок.

Основной экран занимает доступную высоту окна (`100dvh`): все 33 буквы и четыре действия видны одновременно. Поле текста компактное; длинная фраза прокручивается внутри него и автоматически показывает конец при вводе. Количество столбцов подбирается по ширине и высоте оставшегося места, включая изменение панелей браузера при повороте. В горизонтальной ориентации телефона шапка уступает место полю текста и кнопке настроек.

Настройки открываются поверх основного экрана в отдельной панели с собственной прокруткой. Короткое предупреждение видно в шапке, а подробности — в настройках; в горизонтальной ориентации о предупреждении сообщает выделенная кнопка настроек. Панель закрывается кнопкой «Закрыть» или Escape, фокус возвращается к настройкам.

Клавиши занимают максимально доступное место. На небольших экранах приоритет — все инструменты в одном экране; в проверенных размерах зоны букв и действий не меньше 44×44 CSS px. Увеличенный режим увеличивает символы и отдаёт буквам больше высоты за счёт поля текста, оставаясь в границах окна.

Физическая клавиатура: русские буквы, пробел, Backspace; Enter произносит фразу, когда фокус вне кнопки. Tab перемещает фокус; на кнопках Space и Enter выполняют их обычное действие. В списках и переключателях сохраняется стандартное управление клавиатурой.

## Речь и данные

- Язык `ru-RU`, громкость 1, скорость по умолчанию 0.85. Предпочитается русский голос с названием Natural/Neural/Premium/Enhanced, затем голос по умолчанию и локальный. Можно выбрать другой голос.
- Список обновляется по `voiceschanged`. Если русского голоса нет или API недоступен, показано предупреждение; ввод остаётся рабочим.
- Для Й, Ъ, Ь используются «и краткое», «твёрдый знак», «мягкий знак». Названия всех букв заданы явно в `src/alphabet.ts`.
- Для целой фразы текст переводится в обычный регистр: `ВАЛЯ ДОМА` → `Валя дома`. Это помогает избежать чтения прописных слов как аббревиатур. Экранный текст остаётся прописным.
- Каждая новая озвучка отменяет предыдущую. Длинная очередь не создаётся. Отключение озвучки букв и изменение голосовых настроек останавливают текущую речь.
- Текст и настройки хранятся в localStorage этого браузера на этом адресе. Очистка удаляет сохранённый текст. Очистка данных браузера удалит и текст, и настройки; в приватном режиме сохранение может быть временным.
- Приложение не отправляет текст на свой сервер. **Сетевой голос Web Speech API может передавать его службе озвучивания браузера/ОС.** В меню голоса обозначены как «на устройстве» или «сетевой» по свойству `localService`.
- Офлайн-кэш сохраняет интерфейс после первой успешной загрузки. **Офлайн-синтез речи не гарантируется:** нужен установленный локальный русский голос и поддержка со стороны устройства. Если речи нет, проверьте системную громкость, русский голос и выбранный аудиовыход.

## GitHub Pages

Workflow `.github/workflows/deploy.yml` собирает `dist` и публикует его через официальные GitHub Pages Actions. Репозиторий `maxdovbyshdesign-prog/govorilka-3000` подключён как `origin`; публикация запускается при push в `main`.

Чтобы опубликовать последующие изменения, выполните в папке проекта:

```powershell
git add .
git commit -m "Update communicator"
git push origin main
```

Дождитесь успешного workflow **Deploy GitHub Pages** во вкладке [Actions](https://github.com/maxdovbyshdesign-prog/govorilka-3000/actions), затем откройте приложение. Источник публикации в **Settings → Pages → Build and deployment → Source** должен быть **GitHub Actions**. Для ручного повторного деплоя используйте **Run workflow**.

Путь берётся из `actions/configure-pages` автоматически через `VITE_BASE_PATH`; поддерживаются сайт в подпапке репозитория, корневой `USERNAME.github.io` и настроенный в Pages домен. Манифест, иконки и SW используют относительные адреса внутри этого пути. Для самостоятельной сборки под заданный путь:

```powershell
$env:VITE_BASE_PATH = '/govorilka-3000/'
npm.cmd run build
Remove-Item Env:VITE_BASE_PATH
```

В обычной локальной сборке base равен `./`. При обновлении SW ждёт закрытия старых вкладок, чтобы не менять интерфейс посреди набора. Закройте все окна приложения и откройте его снова для перехода на новую версию. Старые кэши удаляются только в области этого приложения; набранный текст сохраняется отдельно.

Основа деплоя: [официальная инструкция Vite](https://vite.dev/guide/static-deploy#github-pages). Голоса и их асинхронная загрузка: [Web Speech API / MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis).

## Добавить на домашний экран

После публикации откройте приложение по HTTPS и дождитесь первой полной загрузки.

- Android / Chrome: меню браузера → «Добавить на главный экран» или «Установить приложение».
- iPhone / iPad / Safari: «Поделиться» → «На экран “Домой”» → «Добавить». Названия могут отличаться в зависимости от версии ОС.
- Если предлагается «Открывать как веб-приложение», включите этот параметр.

Манифест включает PNG 192/512 px, `start_url`, `scope`, standalone-режим; для Safari есть отдельная `apple-touch-icon.png` 180 px. Добавление на экран и качество речи на реальном смартфоне необходимо проверить вручную.

## Проверки

```powershell
npm.cmd run build
npm.cmd test
```

Тесты используют установленный Microsoft Edge на Windows. На Linux/macOS сначала выполните `npx playwright install chromium`. Другой установленный канал можно выбрать через `PLAYWRIGHT_CHANNEL` (например `chrome`). Тесты запускают собственный preview и не переиспользуют уже работающий сервер, чтобы не смешивать разные base path. Если порт 4173 занят, задайте `$env:TEST_PORT = '4175'` перед запуском тестов.

Дополнительная проверка WebKit: `npx playwright install webkit`, затем `$env:TEST_BROWSER = 'webkit'` и `npm.cmd test`. После проверки выполните `Remove-Item Env:TEST_BROWSER`, чтобы вернуть обычный Edge/Chromium. Это настольный тестовый WebKit, а не физический iPhone.

Проверяются сценарии «ВАЛЯ», фраза из двух слов, исправление и повторное произнесение, 33 буквы и специальные знаки, подтверждение очистки, восстановление после перезагрузки, настройки, события клавиатуры, отсутствие/отложенная загрузка голоса, сбой синтеза, недоступное хранилище, офлайн-перезагрузка. Геометрия проверяется на 19 размерах от 320×480 до 1440×900, включая 390×650/700 и 844×290 с уменьшенной высотой из-за браузерных панелей. В двух размерах кнопок проверяются зоны ≥44×44 CSS px, отсутствие перекрытий, нахождение всех букв и действий в видимом окне и отсутствие прокрутки всей страницы. Отдельный сценарий проверяет длинный текст, имитацию боковых вырезов 47 px и нижней безопасной области 21/34 px. Touch и поворот телефона/планшета проверяются с сохранением текста.

Голосовой API в автоматических сценариях подменяется, поэтому они проверяют текст и параметры запросов, отмену очереди и обработку ошибок, **а не слышимое качество речи**. Тест физической русской клавиатуры использует DOM keydown, поскольку Playwright не эмулирует русскую раскладку ОС. Реальный touch, Safari, удобство для конкретного человека и качество звука требуют проверки на его устройстве.

Дополнительная проверка с настоящим Web Speech API и создание снимков (при работающем preview на порту 4173): `node scripts/inspect-preview.mjs`. Она сообщает реальные start/end/error события, сохраняет снимки в `artifacts` и проверяет офлайн-перезагрузку; наличие событий не заменяет прослушивание.

PNG-иконки уже включены в `public`. При необходимости их можно пересоздать на Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/generate-icons.ps1`.
